## 1. Статусы

| Статус | Значение |
|---|---|
| `NOT_STARTED` | Реализация не начиналась |
| `IN_PROGRESS` | Работа начата, но требование выполнено не полностью либо ожидает проверки |
| `IMPLEMENTED` | Реализация присутствует в коде/сценах, но не подтверждена полным приёмочным прогоном |
| `VERIFIED` | Реализация подтверждена применимой автоматической или ручной runtime-проверкой; Git SHA обязателен для приёмки этапа |
| `BLOCKED` | Выполнение невозможно до устранения указанной блокировки |
| `DEFERRED` | Требование осознанно перенесено на более поздний этап |

Статический просмотр архива позволяет установить максимум `IMPLEMENTED`. Статус `VERIFIED` допускается после подтверждённого запуска; SHA коммита обязательно фиксируется перед окончательной приёмкой прототипа.

## 3. Результат текущей итерации от 2026-08-01

### 2026-08-01 — длительный streaming soak-profiler `TASK-026`

**Основание:** разделы 10.1–10.4, 34.3 и Прототип B раздела 39 PDF-ТЗ; очередь журнала после подтверждения `TASK-025`.

**Полученное runtime-доказательство предыдущей итерации:**

- проект успешно собран и запущен локально в Godot;
- HUD показал `TASK-025 stress: PASS`;
- фактические значения: `rev=13`, `cancel=0`, `stale=48`, `9/9`, `queue=0`, `workers=0`;
- HUD показал `ошибки: 0`, переход вернулся в состояние `стабильно`;
- пользователь подтвердил нормальный визуальный результат и принятие предшествующих итераций;
- прежний запуск по `F9` требовал повторного нажатия из-за hotkey редактора Godot, поэтому короткий stress-test перенесён на `F10`.

**Изменения статусов по подтверждению пользователя:**

- `TASK-005`: `IN_PROGRESS` → `VERIFIED` — успешный запуск сцены подтверждает отсутствие ошибок компиляции текущего снимка;
- `TASK-009`: `IN_PROGRESS` → `VERIFIED` — предыдущая проверка управления и столкновений принята пользователем;
- `TASK-011`: `IN_PROGRESS` → `VERIFIED` — предыдущая итерация простой стрельбы принята пользователем;
- `TASK-023`: `IMPLEMENTED` → `VERIFIED`;
- `TASK-024`: `IMPLEMENTED` → `VERIFIED`;
- `TASK-025`: `IN_PROGRESS` → `VERIFIED`;
- `PB-040`–`PB-043`, `PB-050`–`PB-052`, `PB-060`, `PB-062`, `PB-063`: → `VERIFIED`;
- `PB-ACC-001`–`PB-ACC-010`: → `VERIFIED`;
- `PB-061` остаётся `IMPLEMENTED` до длительного теста на отсутствие накопления ресурсов.

**Реализовано в `TASK-026`:**

- клавиша `P` запускает и повторным нажатием досрочно останавливает soak-test;
- длительность, задержка между переходами, радиус маршрута, timeout одного перехода и допустимый рост managed memory задаются экспортируемыми параметрами;
- тест временно блокирует физический процесс игрока, сохраняет точную исходную позицию и hysteresis-центр, затем проходит замкнутый маршрут только по соседним чанкам;
- новый переход выдаётся только после полного idle-состояния предыдущей revision;
- после каждого стабилизированного перехода проверяются полный active set, соответствие каждого чанка актуальному `ChunkSpec`, наличие visual mesh, точное число collision shapes и число вершин верхней поверхности;
- на протяжении теста фиксируются пиковые active chunks, очередь, workers и managed memory;
- baseline и final managed memory измеряются после принудительной сборки мусора; превышение экспортируемого лимита приводит к `FAIL`;
- worker error, зависшая очередь, timeout перехода, отсутствующий mesh/collision, лишняя collision или недостаточное число переходов приводят к `FAIL`;
- финальный `PASS` возможен только после возврата в исходный центр, `9/9`, пустых очередей и `workers=0`;
- HUD получил отдельную строку `TASK-026 soak (P)`; Output печатает длительность, moves, idle samples, revisions, cancelled/stale/failed, mesh/collision, vertices, baseline/peak/final memory и пики очереди;
- `TerrainChunk` предоставляет read-only диагностические свойства фактического наличия mesh/collision и размера верхней поверхности;
- высота HUD увеличена;
- README и журнал актуализированы.

**Статус текущей итерации:**

- кодовая часть `TASK-026` — `IMPLEMENTED`;
- `TASK-026` остаётся `IN_PROGRESS` до локальной строки `TASK-026 soak (P): PASS`;
- Прототип B остаётся `IN_PROGRESS` только из-за незавершённого длительного resource-soak и отсутствующего Git SHA.

**Ограничение проверки:** в рабочей среде отсутствуют Godot и .NET SDK. Выполнены статический аудит C#, проверка state machine, маршрута, критериев PASS/FAIL, ресурсов сцены и целостности проекта. Фактический 120-секундный прогон выполняется локально пользователем.

## 10. Ручной smoke test текущей итерации

После сборки выполнить один непрерывный прогон:

1. Открыть `src/Game.Client/project.godot`, дождаться импорта C# и выполнить сборку.
2. Нажать `F5`; должна открыться сцена `TerrainChunkPrototype`.
3. Дождаться `стабильно`, `Активно: 9/9`, `очередь: 0`, `workers: 0/N`, `ошибки: 0`.
4. Для короткой регрессии нажать `F10`; дождаться `TASK-025 stress (F10): PASS`. `F9` больше не используется.
5. Нажать `P`. Игрок должен начать автоматический замкнутый маршрут, а HUD — показать `TASK-026 soak (P): RUNNING`.
6. По умолчанию тест длится 120 секунд. Каждый следующий центр выдаётся только после стабилизации предыдущей revision; зависание одного перехода дольше 20 секунд должно дать `FAIL`.
7. Во время теста HUD должен сохранять `ошибки: 0`; очередь и workers могут быть ненулевыми только во время перехода и обязаны возвращаться к нулю между переходами.
8. Дождаться строки `TASK-026 soak (P): PASS`. Итоговая строка Output должна содержать `failed=0`, `active=9/9`, `meshes=9`, ожидаемое число collisions, `pending=0`, `apply=0`, `ready=0`, `completed=0`, `workers=0`, а также baseline/peak/final managed memory.
9. Любой `FAIL`, timeout, worker error, отсутствующий mesh/collision, лишняя collision либо превышение memory-limit считать незакрытым дефектом; сохранить полную итоговую строку Output.
10. Убедиться, что после теста игрок вернулся в исходную точку, управление восстановлено и HUD снова показывает стабильные `9/9`. Повторное нажатие `P` во время теста должно корректно остановить его и также вернуть игрока.
11. Нажать `F1`–`F4`: переключение диагностики не должно запускать новые worker-job или менять collision.
12. Записать итог `TASK-026`, duration, moves, idleSamples, managedDelta, peakQueue, peakWorkers и SHA коммита в раздел 11.
